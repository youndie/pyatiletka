# Технический бриф: «Пятилетка»

| | |
|---|---|
| Дата | 2026-11-12 |
| Репозиторий | новый — `youndie/pyatiletka`, публичный, MIT (имя свободно на 12.11.2026) |
| Платформы | desktop (JVM, окно в рамке appframe) и web (wasmJs); широкая раскладка 1280×800 и узкая 390×844. Android — следующим этапом, не в первой версии |
| Стек | Compose Multiplatform без сервера: `core`, `collector`, `app`, `skin-plakat`, `skin-toon` — *решено*, см. §8 |
| Документация | `docs/` в репозитории, формат docs-bootstrap; проза по-русски, идентификаторы и код по-английски |
| Статус документа | артефакт ветки в `research/`; удаляется до вливания ветки |

Как разделы становятся документацией: §8 и §10 — исследовательский документ
(`docs/research/research-architecture.md`); §3 кормит бизнес-правила фич; §4 → `features/`,
§5 → `screens/`, §6 → `api/`, §7 → `services/` пишутся черновиками в PR, который остаётся
открытым, пока код не даст им якоря; §9 становится бэклогом.

## 1. Задача и аудитория

Владелец портфеля из полусотни репозиториев каждый день выясняет одно и то же: где красный
main, какие PR ждут вливания, сколько пунктов бэклога закрыто и какие ждут его ответа. Сегодня
это делается скриптами и вкладками GitHub. «Пятилетка» показывает это одной доской: строка на
репозиторий, сводка сверху, выполнение плана в процентах.

Вторая задача равна первой по весу: доска — первый боевой потребитель двух UI-китов,
plakat-ui и toon-ui, до их выпуска на Maven Central. Каждый экран собран дважды, по разу на
кит, поверх одного состояния. Всё, чего киту не хватило, становится пунктом в бэклоге кита.
Аудитория первой версии — один человек, владелец; публичная страница показывает ту же доску
по открытым репозиториям любому, кто пришёл посмотреть на киты.

## 2. Объём

**В первой версии:**

- доска: строка на репозиторий (состояние CI на основной ветке, открытые PR, выполнение
  плана, пункты, ждущие владельца), сводка по портфелю, фильтр и поиск;
- карточка репозитория: упавшие проверки, список открытых PR, список открытых пунктов бэклога,
  ссылки на GitHub;
- десктоп сам собирает данные по таймеру с локальным токеном, хранит последний удачный
  снимок и показывает его, когда сеть недоступна;
- веб-страница читает готовый снимок, который раз в час кладёт рядом со страницей workflow;
- два скина — plakat-ui и toon-ui — с переключением на ходу, по две-три темы в каждом;
- учёт находок: каждое обходное решение из-за кита заведено issue в репозитории кита.

**Сознательно вне первой версии:**

- любые действия записи (влить PR, перезапустить CI) — доска только читает;
- история и графики во времени — снимки копятся в истории ветки `gh-pages`, но не читаются;
- подсчёт плана у репозиториев с плоским `BACKLOG.md` — формат у каждого свой;
- уведомления, трей, автозапуск;
- Android- и iOS-сборки;
- английская локализация: строки лежат в ресурсах, перевод — отдельный пункт позже;
- свой сервер: решение владельца от 12.11, данные приходят снимком.

## 3. Домен

| Сущность | Идентификатор | Владелец | Заметки |
|---|---|---|---|
| `Snapshot` | `takenAt` | — | вся доска целиком на один момент: версия схемы, список владельцев, список `Repo` |
| `Repo` | `owner/name` | `Snapshot` | видимость `Public` / `Private`; основная ветка; время последнего push |
| `MainStatus` | — | `Repo` | закрытый набор: `Green`, `Red`, `Running`, `None` (у коммита нет проверок) |
| `FailedCheck` | имя проверки | `Repo` | только при `Red`; имя и ссылка |
| `PullRequest` | номер в репозитории | `Repo` | заголовок, автор `Human` / `Bot`, черновик, возраст, состояние проверок: `Ready`, `Failing`, `Running`, `NoChecks` |
| `Plan` | — | `Repo` | форма: `Items` (индекс docs-bootstrap), `Flat` (один `BACKLOG.md`), `None`; для `Items` — счётчики `done`, `open`, `wip`, `question`, `dropped` |
| `BacklogItem` | `B-NN` | `Plan` | только незакрытые: заголовок, статус `Open` / `Wip` / `Question`, приоритет, ссылка |
| `Settings` | — | локально | скин, тема, владельцы, период обновления, источник токена; секретов не содержит |

Тенантности нет: один пользователь, данные не делятся. Единственная граница доступа —
видимость репозитория: всё, что публикуется (снимок страницы, эталоны, примеры в доках),
содержит только `Public`.

## 4. Фичи

Сценарии — *целевые*: задуманное поведение, сверяется с кодом до того, как документ фичи
станет `active`.

### feature-board: доска портфеля

**Обзор.** Одна таблица отвечает на вопрос «куда смотреть первым». Сверху сводка: выполнение
плана по портфелю, число красных main, открытых PR и пунктов, ждущих владельца.

**Бизнес-правила:**

- план репозитория = `done + open + wip + question`; `dropped` в план не входит;
- выполнение = `done / план`, округление вниз до целого процента; 100 % показывается только
  когда `open + wip + question = 0`;
- выполнение портфеля = сумма `done` / сумма планов по репозиториям с формой `Items`;
- «ждут владельца» = число пунктов со статусом `Question`;
- порядок строк по умолчанию: `Red` main, затем есть PR `Failing`, затем есть `Question`,
  затем есть открытые PR, затем по времени последнего push;
- фильтры: все, красные (`Red` main или PR `Failing`), с PR, ждут меня; поиск по имени
  репозитория, без учёта регистра;
- у репозитория с формой `Flat` или `None` вместо процента стоит пометка, в сводку он не входит.

**Модули:** `core`, `app`, `skin-plakat`, `skin-toon`. **Экраны:** screen-board.
**Эндпоинты:** endpoint-snapshot (web); на десктопе — «нет API», сбор в процессе.

**Сценарии (целевые):**

- *Обычный день* — дан снимок из §5a; когда доска открыта, первой стоит `youndie/tacku`
  (красный main), сводка показывает 95 %, 1 красный, 12 PR, 7 ждут.
- *Фильтр ничего не нашёл* — дан тот же снимок; когда в поиске набрано `zzz`, доска
  показывает состояние `NoMatches` с кнопкой сброса, сводка не меняется.
- *План выполнен не до конца* — дан репозиторий с `done = 179`, `open = 1`; тогда выполнение
  показывает 99 %, а не 100 %.

### feature-repo-detail: карточка репозитория

**Обзор.** Что именно красное, какие PR открыты и в каком они состоянии, какие пункты плана не
закрыты. Каждая строка ведёт на GitHub.

**Бизнес-правила:**

- карточка строится из того же снимка, что доска: своей загрузки у неё нет;
- PR отсортированы: `Failing`, `Ready`, `Running`, `NoChecks`; внутри — старые выше;
- пункты плана отсортированы: `Question`, `Wip`, `Open`; внутри — по приоритету;
- при `Red` упавшие проверки стоят первыми на карточке;
- репозиторий без открытых PR и незакрытых пунктов при `Green` показывает состояние `Quiet`.

**Модули:** `core`, `app`, `skin-plakat`, `skin-toon`. **Экраны:** screen-repo.
**Эндпоинты:** нет (данные из снимка).

**Сценарии (целевые):**

- *Красный main* — дан `youndie/tacku` из §5a; когда открыта карточка, сверху стоят две
  упавшие проверки, ниже PR и пункты.
- *Нечего делать* — дан `youndie/plakat-ui` (73 из 73, PR нет, `Green`); тогда карточка
  показывает состояние `Quiet`.
- *Плана нет* — дан `youndie/proba` (`Plan.None`); тогда раздел плана заменён пометкой, PR
  показаны как обычно.

### feature-refresh: свежесть данных

**Обзор.** Доска всегда показывает последний удачный снимок и честно говорит, насколько он стар.

**Бизнес-правила:**

- десктоп собирает снимок при запуске, затем каждые 5, 15 или 60 минут (по умолчанию 15) и
  по кнопке; удачный снимок пишется на диск;
- веб читает `snapshot.json` рядом со страницей при открытии и по кнопке;
- снимок считается устаревшим, если он старше двух периодов (десктоп) или трёх часов (веб),
  либо если последняя попытка обновления не удалась;
- неудача при наличии старого снимка даёт состояние `Stale` с причиной; без снимка — `Error`;
- публичный режим сборщика отбрасывает любой репозиторий с видимостью не `Public` и падает,
  если такой попал в результат.

**Модули:** `core`, `collector`, `app`. **Экраны:** screen-board. **Эндпоинты:** endpoint-snapshot.

**Сценарии (целевые):**

- *Сеть пропала* — дан десктоп со снимком от 21:17 вчера; когда обновление не удалось, доска
  показывает прежние строки и полосу «снимок от 11 ноября, 21:17 — нет связи с GitHub».
- *Первый запуск без сети* — снимка на диске нет; когда сбор не удался, доска показывает
  `Error` с кнопкой повтора.
- *Снимок ещё не опубликован* — веб-страница получает `404` на `snapshot.json`; тогда она
  показывает `Error`, а не пустую доску.
- *Неизвестная версия схемы* — `snapshot.json` с `schemaVersion`, которого клиент не знает;
  тогда `Error` с текстом «страница старее снимка — обновите вкладку».

### feature-skins: два скина на одном состоянии

**Обзор.** Каждый экран существует в plakat-ui и в toon-ui. Переключение на ходу не теряет
место: выбранный репозиторий, фильтр и поиск остаются.

**Бизнес-правила:**

- скины не знают друг о друге: `skin-plakat` зависит только от plakat-ui, `skin-toon` только от
  toon-ui; общего слоя «компонентов поверх китов» нет;
- у каждого состояния каждого экрана есть эталон в обоих скинах;
- темы: plakat — `Paper`, `BlackPaper`; toon — `InkGouacheLight`, `InkGouacheNight`, `BrightCel`;
- выбор хранится локально; на вебе его задаёт и адрес: `?skin=toon&theme=night`;
- обходное решение из-за кита разрешено только вместе с issue в репозитории кита и
  комментарием `// kit: <ссылка>` в месте обхода.

**Модули:** `app`, `skin-plakat`, `skin-toon`. **Экраны:** screen-board (состояние
`AppearanceSheet`). **Эндпоинты:** нет.

**Сценарии (целевые):**

- *Переключение на ходу* — открыта карточка `youndie/kachok` в plakat; когда выбран скин toon,
  открыта та же карточка, фильтр и поиск на доске прежние.
- *Адрес задаёт скин* — веб-страница открыта с `?skin=toon`; тогда первый кадр уже в toon.

### feature-settings: откуда и как собирать (только десктоп)

**Обзор.** Чьи репозитории показывать, как часто обновлять и откуда взять токен.

**Бизнес-правила:**

- токен берётся из `gh auth token` или из переменной `PYATILETKA_GITHUB_TOKEN`; на диск и в
  логи он не пишется, поля для ввода токена нет;
- владельцы — список логинов пользователей и организаций; добавляемый логин проверяется
  запросом к GitHub;
- без токена доска показывает `NoToken` со ссылкой в настройки.

**Модули:** `collector`, `app`, `skin-plakat`, `skin-toon`. **Экраны:** screen-settings,
screen-board (`NoToken`). **Эндпоинты:** нет.

**Сценарии (целевые):**

- *Токена нет* — `gh` не установлен, переменная пуста; тогда настройки показывают
  `TokenMissing` с двумя способами его дать.
- *Токен отвергнут* — GitHub отвечает `401`; тогда `TokenRejected`, старый снимок остаётся.
- *Нет такого владельца* — введён логин `youndi`; тогда поле показывает ошибку
  `OwnerNotFound`, список не меняется.

## 6. API

Своего сервера нет. Единственный контракт между частями продукта — файл снимка.

### endpoint-snapshot: снимок портфеля

Класс контракта: `core: Snapshot`. Сервис: статический файл на GitHub Pages, пишет `collector`.

| Метод | Путь | Уровень | Мин. роль | Запрос | Ответ | Ошибки | В публичной схеме? |
|---|---|---|---|---|---|---|---|
| `GET` | `/snapshot.json` | аноним | — | — | `Snapshot` | `404` снимок не опубликован; тело не разбирается; неизвестный `schemaVersion` | да |

Соглашения: JSON kotlinx.serialization, `ignoreUnknownKeys = true`, времена в ISO-8601 UTC,
целое поле `schemaVersion` в корне. Клиент, встретивший версию новее своей, показывает `Error`.

Внешняя зависимость, не наш API: GitHub GraphQL. Запрос и его цена описываются в документе
сервиса `collector`, не здесь.

## 8. Решения и гипотезы

| Решение / утверждение | Почему | Проверено по / *гипотеза* |
|---|---|---|
| Сервера нет; данные — снимок | решение владельца 12.11: цель — обкатать киты, а не сервис | ответ владельца в брифинге |
| CI, число открытых PR и индекс бэклога приходят одним запросом GraphQL | один запрос вместо сотни вызовов REST | проба 12.11: 48 публичных репозиториев, `statusCheckRollup` + `pullRequests.totalCount` + `object(expression:"HEAD:backlog.md")`, `rateLimit.cost = 1` |
| Тот же запрос со списком PR и именами упавших проверок укладывается в один вызов | карточке нужны заголовки PR и проверки | *гипотеза* — замерить цену и время в пункте 2 |
| Индекс бэклога разбирается по меткам | счётчики плана без чтения файлов пунктов | docs-bootstrap `origin/main`, словарь `MARK`: `[ ]` open, `[~]` wip, `[x]` done, `[?]` question, `[-]` dropped; блок между `<!-- BEGIN INDEX -->` и `<!-- END INDEX -->`, заголовки `## Open (N)`, `## Closed (N)` — прочитано в `appframe` и `plakat-ui` |
| Индекс есть у 27 из 48 публичных репозиториев, у 8 — плоский `BACKLOG.md`, у 13 — ничего; самый большой индекс 36,7 КБ | отсюда формы `Items` / `Flat` / `None` | запрос GraphQL 12.11 |
| Токен workflow читает чужие публичные репозитории и не видит приватных | публичность снимка держится на праве токена, а не только на фильтре | *гипотеза* — пункт 3; запасной путь — отдельный токен только на чтение публичного |
| Раз в час достаточно; расписание GitHub может запаздывать | порог устаревания на вебе — три часа | *гипотеза* — посмотреть фактические интервалы за неделю |
| plakat-core `0.1.0.15`, toon-core `0.1.0.13` из `reposilite.kotlin.website/snapshots` | киты ещё не на Central — ради этого продукт и нужен | `maven-metadata.xml`, 12.11 |
