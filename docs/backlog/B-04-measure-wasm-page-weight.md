# B-04 — Замер: вес и первая отрисовка wasm-страницы с двумя китами

Страница — витрина китов. Приемлема ли первая загрузка wasm с двумя китами и их шрифтами — гипотеза ([исследование, риск 5](../research/research-architecture.md)).

- **Решение и причина.** Замерить на каркасе B-01, до экранов: если вес неприемлем, решение (ленивая загрузка второго кита, урезанные шрифты) меняет устройство `app`.
- Порог называет владелец после замера (открытый вопрос 4 исследования).

- AC: размер и время до первого кадра записаны, владелец назвал порог.
- Якоря: `app/src/wasmJsMain/`, `measurements/wasm/`.

## Замер (12.11.2026)

Подробности, скрипты и сырые прогоны — в [`measurements/wasm/`](../../measurements/wasm/README.md).

- **Вес:** 4 608 КиБ по сети в gzip (как отдаёт GitHub Pages) с одним китом в бандле, 4 724 КиБ —
  с двумя; в toon-теме ещё 242 КиБ шрифтов и текстуры. Из них wasm skiko — 3,3 МиБ, тот же файл,
  что у страницы примеров toon-ui.
- **Первый кадр** (медиана 5 холодных прогонов): без ограничений — 1,04–1,07 с, доска со шрифтами
  кита — 1,13–1,15 с; Slow 4G (Lighthouse) — 24,5–25,1 с и 25,7–27,6 с.
- **Второй кит:** +116 КиБ (+2,5 %) и +0,6 с на Slow 4G. Ленивая загрузка кита не нужна. Заметно
  уменьшить страницу можно только другим хостом (brotli, около −0,9 МиБ) или меньшим skiko.
- Попутно: пока `Shell` не рисовал toon, toon-ui в бандле не было — оптимизатор выбрасывал его как
  мёртвый код. С [B-16](B-16-live-skin-switch-and-url.md) `Shell` рисует оба кита, и страница — это
  плечо `two-kits` этого замера.

## Вопрос владельцу

Какой порог принять для страницы-витрины? Варианты:

1. **Принять как есть.** Около 1 с на быстрой сети, около 25 с на медленной мобильной; вес — цена
   Compose для web, а не китов.
2. **Порог по времени на быстрой сети** (например, первый кадр ≤ 2 с при `local`) и сторож в CI,
   который его держит. Медленная мобильная сеть тогда вне цели.
3. **Порог, требующий другого хоста** (например, ≤ 4 МиБ по сети): brotli на своём хосте вместо
   GitHub Pages. Это меняет [B-17](B-17-publish-page-and-hourly-snapshot.md).

Рекомендация — 1 или 2: ни один порог, достижимый на GitHub Pages, не отличается от текущего веса
больше чем на 2,5 %.
