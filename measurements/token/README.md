# Замер: что видит токен workflow (B-03)

12.11.2026. `probe.sh` печатает только числа: имя приватного репозитория, если бы токен его
видел, не должно попасть в публичный лог Actions.

| Токен | Где | Репозиториев владельца в списке | Из них не `PUBLIC` | Снимок `portfolio.graphql` (по 25) | Тексты `backlog.md` | Лимит GraphQL в час |
|---|---|---|---|---|---|---|
| `GITHUB_TOKEN` этого репозитория | Actions, `ubuntu-latest`, событие `push` ([прогон 43239756668](https://github.com/youndie/pyatiletka/actions/runs/43239756668)) | 54 | 0 | 54 репозитория, 3 страницы, 39 очков, 7 с | 28 из 28 | 5000 |
| токен `gh` владельца | мак, контроль | 60 | 6 | 54 репозитория, 3 страницы, 39 очков, 8 с | 28 из 28 | 5000 |

Выводы:

1. Токен workflow читает чужие публичные репозитории владельца целиком — проверки, PR и тексты
   бэклогов, — и приватных не видит вовсе: запрос без фильтра видимости вернул только `PUBLIC`.
   Публичность снимка держится уже на праве токена, фильтр `--public-only` — второй замок.
2. Снимок тем же запросом стоит столько же, сколько с токеном владельца (39 очков, 3 страницы),
   а лимит у токена — те же 5000 очков в час: ежечасный снимок занимает меньше процента.
3. Прогон был по событию `push`, а не по расписанию. Токен тот же — `GITHUB_TOKEN` репозитория;
   расписание со снимком проверяет [B-17](../../docs/backlog/B-17-publish-page-and-hourly-snapshot.md),
   где приёмка — `snapshot.json`, дважды обновлённый самим workflow.

Повторить: `gh workflow run token-probe.yaml` (после вливания — с `main`) или локально
`GH_TOKEN=... measurements/token/probe.sh youndie`.
